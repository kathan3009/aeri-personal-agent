# Provider activation checklist

All secrets belong in the API `.env` or the deployment secret manager. Run `npm run setup:local` once; it preserves existing files. The mobile app needs only an API address and the private access code.

1. **Neon**: create a Postgres database; paste its connection string into `DATABASE_URL`. The API creates `agent_state` automatically. Use a dedicated branch for the hackathon. Restart the API and confirm `GET /v1/bootstrap` reports `providers.neon=true`.
2. **Neon AI Gateway**: redeem the gateway token and bare branch host. Set `NEON_AI_GATEWAY_API_KEY` and `NEON_AI_GATEWAY_BASE_URL` (without `/v1`). Keep `NEON_AI_GATEWAY_MODEL=gpt-5-mini` unless the catalog differs. The Mastra agent uses the Gateway's OpenAI-compatible chat endpoint. Test an open-ended question in Agent and inspect the reply.
3. **Gemini**: set `GEMINI_API_KEY`. The direct model processes public YouTube URLs through Interactions; short kitchen clips go inline and larger clips through the Files API. `GEMINI_VIDEO_MODEL=gemini-3.8-flash` is the documented default. Voice notes upload through the Files API and use `GEMINI_AUDIO_MODEL=gemini-3.5-transcribe`; uploaded media is deleted after processing. Update either to a model enabled on your account. Test one real recipe, one kitchen clip and one voice note; check extracted quantities before relying on a cart. Direct Gemini usage is separate from the sponsor's Gateway credits.
4. **Kernel**: set `KERNEL_API_KEY` and `KERNEL_RETAILER_URL` for the single store you will demo. The browser opens only after cart approval. When Gateway is also configured, the bounded Mastra browser agent can search/click approved products using constrained Playwright actions. Rehearse login, store selection, stock, quantities and cart contents in the live browser. The user completes checkout. A failed browser agent leaves a live-view handoff rather than claiming success.
5. **Exa**: set `EXA_API_KEY`. `POST /v1/carts/:id/research` returns suggested links. It does not set the retailer's stock or price.
6. **Vapi**: create a saved assistant and inbound number. Set `VAPI_PHONE_NUMBER` in E.164, `VAPI_ALLOWED_CALLER` to your exact caller number, and a strong `VAPI_WEBHOOK_SECRET`. Create a Vapi Custom Credential that sends this secret as `X-Vapi-Secret` without a Bearer prefix; attach its `credentialId` to the saved Function tool/server configuration at `/webhooks/vapi`. Define `read_memory` (no arguments), `remember` (`text`, `confirmed:true`), and `start_recipe` (`url`, `confirmed:true`). The endpoint accepts current `toolCallList` name/parameters and legacy function/arguments shapes and returns correlated results. Place and verify a real call before demoing this channel. Vapi charges are separate from listed sponsor credits.
7. **AgentMail**: create a private inbox and a `message.received` webhook to `/webhooks/agentmail`; set the returned Svix webhook secret as `AGENTMAIL_WEBHOOK_SECRET`. Forward a receipt. Aeri logs signed email evidence for review and never silently treats email text as a delivered order.
8. **Fly.io**: build the API container from the root Dockerfile. Set `APP_ACCESS_TOKEN`, `DATABASE_URL`, and provider secrets with `fly secrets set`; set `HOST=0.0.0.0`. Do not deploy until the sponsor credit scope and billing settings are understood. Use `fly.template.toml` as a starting point and choose an unused app name.

This code does not claim that any sponsor account is already redeemed or connected. Each provider turns on only when its credentials are supplied and the relevant live smoke test succeeds.
